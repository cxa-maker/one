# 嘉乐OZON——AI 适配基线

> 本文件是 `OZON_AI_ERP_TRADEMIND` 的项目边界和迁移约束。产品名为 `嘉乐OZON——AI`。它用于让后续开发、AI Agent 和浏览器采集器遵循同一套事实来源，不把演示数据当成真实商品数据。

## 1. 基座和目标

本项目以 TradeMind 的任务、采集器、AI 批次、商品草稿、发布检查和操作审计为基础，逐步适配我们的 OZON/rFBS 工作流。旧项目 `D:\工作\OZON_AI_ERP` 保留为回滚和数据参考，不直接覆盖新基座。

目标不是复制一个静态页面，而是形成下面这个可追踪闭环：

```text
1688 商品链接 或 OZON 竞品链接
        -> 浏览器/采集器读取页面
        -> 原始证据和结构化商品档案
        -> 规则校验、来源标记、待确认字段
        -> AI 生成俄语标题/卖点/描述/图片和视频任务
        -> 人工预览和修改
        -> OZON 草稿
        -> 人工确认后发布
```

## 2. 两类来源必须分开

### 1688：采购证据源

1688 只用于：

- 采购价和阶梯价；
- SKU、颜色、规格和套装关系；
- 供应商信息和采购链接；
- 页面明确提供的商品尺寸、包装尺寸和重量文本；
- 供应商图片和视频只能进入素材参考区，不能自动变成 OZON 发布素材。

1688 的字段不能覆盖 OZON 的市场字段，也不能把供应商的“商品尺寸”直接当成“打包尺寸”。若页面没有明确包装数据，`packageLengthMm`、`packageWidthMm`、`packageHeightMm`、`packageWeightG` 必须保持 `pending`。

### OZON：竞品和市场证据源

OZON 竞品页用于：

- 竞品标题、类目路径和公开属性；
- 价格、评价、销量等市场参考数据；
- 竞品图片、视频封面和公开媒体链接，进入待处理素材区；
- 竞品描述和卖点，作为 AI 改写输入，不直接写入最终商品档案；
- 竞品的发货模式、尺寸和重量只能作为市场参考，不替代我们的真实履约数据。

OZON 采集结果必须标注为 `competitor` 或 `market_reference`。它不能自动变成我们的采购成本、库存、包装尺寸或可发布 SKU。

## 3. 商品档案数据规则

所有商品字段都必须有来源和状态，建议沿用以下语义：

- `collected`：页面或 API 明确读取到，保留原始值和证据；
- `candidate`：可以作为候选，但仍需人工确认或 AI 处理；
- `pending`：未读取到、冲突或需要人工填写；
- `confirmed`：人工检查后确认，可进入下一阶段；
- `rejected`：明确不采用，不能再次被默认值覆盖。

每个字段至少保留：`source`、`sourceUrl`、`recordId`、`confidence`、`evidence`、`updatedAt`。发生冲突时保留两份证据并记录 `conflicts`，不静默选择一个值。

禁止事项：

1. 新建商品不能填入演示链接、演示标题、演示 SKU、演示价格或演示库存。
2. 采集失败时不能沿用上一次商品的数据。
3. 未采集的字段显示“待采集/待确认”，不能显示看起来像真实数据的数字。
4. 竞品价格不能进入采购成本；供应商报价也不能直接当成 OZON 售价。
5. 尺寸和重量未确认时，利润计算必须标记为临时估算，不能显示为最终利润。

## 4. 当前已经接入的新能力

当前分支 `ozon-erp` 已接入 TradeMind Collector Provider：

- `collector/src/providers/sourceOzon/index.ts`：Playwright 只读采集入口；
- `collector/src/providers/sourceOzon/ozon-product.js`：复用现有 OZON 页面结构化采集器；
- `collector/src/providers/registry.ts`：注册 `ozon` provider；
- `collector/src/providers/sourceOzon/__tests__/index.test.ts`：URL 识别和 provider 能力测试。

Provider 会把 OZON 页面结果映射为 TradeMind 的 `NormalizedProduct`，并把原始 `schemaVersion`、页面 payload、证据、冲突、待确认字段和质量信息放入 `raw`，便于重放和后续解析。

目前的明确边界：

- 采集器编译通过，单元测试通过；
- 管理端构建通过；
- OZON 实页本次 smoke test 受当前网络 `ERR_CONNECTION_CLOSED` 影响，尚未算作真实采集成功；
- 目前是只读 Provider，不会自动发布商品；
- 后端 Go 尚未在本机验证，因为当前环境没有 Go；
- Edge 已登录会话、OpenCLI 和 1688 新旧模板的统一接入仍是后续工作，不能假装已经完成。

## 5. 下一阶段实现顺序

### 阶段 A：采集闭环

1. 保留 TradeMind 的任务、事件、重试和审计模型。
2. 将 OZON Provider 的 `raw` 结果落到采集任务和商品档案。
3. 接入现有 OZON Edge 插件的登录态采集，避免把登录页面误判为商品页。
4. 将现有 `source1688` provider 与采购证据字段接通；新旧 1688 模板分别保留适配器，不用一套脆弱选择器硬撑。
5. 在管理端提供“采集结果预览”，显示每个字段的来源、置信度和待确认原因。

### 阶段 B：商品草稿

1. 采集完成后只生成草稿，不直接写入正式发布字段。
2. 根据真实标题、属性和类目候选匹配 OZON 类目与属性。
3. 类目或属性没有可靠匹配时进入人工队列，并展示候选及证据。
4. 草稿页区分采购信息、竞品信息、发布信息和人工确认信息。
5. 只有必填字段全部通过发布检查，且图片、视频、包装尺寸和重量已确认，才允许进入发布队列。

### 阶段 C：AI 内容和素材

AI API 只接收结构化商品档案和明确标注的素材，不接收一团未经区分的网页数据。输出分成独立批次：

- `text`：俄语标题、短卖点、描述和标签；
- `image`：主图、场景图、使用图、尺寸图、包装清单图等候选图；
- `video`：10 至 15 秒商品短视频任务，记录脚本、镜头、人物、商品引用图和生成状态。

每个 AI 结果都保留 prompt、模型、输入素材哈希、输出地址、生成时间和人工审核状态。AI 不能凭空补尺寸、材质、功率、品牌或安全承诺；缺失事实必须输出待确认。

### 阶段 D：OZON 发布

先通过 Seller API 做只读类目、属性、商品状态和草稿校验，再由发布检查器确认：

- 类目和属性合法；
- 标题和描述为俄语且无未处理的中文水印、联系方式或品牌风险；
- 图片顺序和数量符合 OZON 要求；
- 视频存在且可播放；
- 包装长宽高和重量是已确认值；
- rFBS 仓库、备货时间、库存、价格和物流成本已经人工确认。

最后一步仍是人工点击发布。取消、删除、改库存、改价格和发货等高风险写操作必须单独确认，并写入审计日志。

## 6. 数据迁移策略

旧项目的 JSON 不直接复制成新系统的正式数据库。迁移分三步：

1. 先把旧 JSON 当作只读原始导入，保留文件哈希和导入时间；
2. 映射到新的商品档案、来源证据、媒体资产和待确认字段；
3. 经过人工抽样核对后，才标记为 `confirmed`。

旧数据中出现的演示记录、空字段、乱码、历史竞品数据和无法证明来源的数据必须进入导入问题清单，不能自动成为新商品默认值。

## 7. 验收口径

一个功能只有同时满足以下条件，才能说“可用”：

- 有真实输入链接；
- 能展示采集原文或结构化证据；
- 采集失败时有明确失败原因；
- 刷新或重启后任务和草稿仍存在；
- 未采集字段不会出现伪造默认值；
- AI 输出能回溯到输入商品和素材；
- 上架前可人工预览、修改、驳回；
- 高风险操作不会静默执行。

“页面能打开”“按钮能点击”不等于完成验收。
